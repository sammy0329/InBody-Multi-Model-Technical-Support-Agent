Technical Challenges & Solutions
Challenge 1

기종 간 정보 오염 방지

4개 기종은 각각 별도의 매뉴얼·에러코드 체계를 보유. 기종별 RAG 컬렉션을 분리하지 않으면 다른 기종의 정보가 섞여 부정확한 안내로 이어짐.

Solution — 3계층 격리 아키텍처
Layer 1: ChromaDB 기종별 독립 컬렉션 (물리적 격리)
Layer 2: where: {model: '770S'} 메타데이터 필터 (논리적 격리)
Layer 3: 가드레일 regex로 다른 기종명 패턴 감지 (후처리 격리)
100% 격리 — 4×4 기종 조합 16케이스 전수 검증
Challenge 2

할루시네이션 0% 달성

LLM이 미등록 에러코드에 대해 그럴듯한 추측 응답을 생성할 위험. 기술 지원에서 추측은 곧 오진.

Solution — 결정론적 가드레일 우선 설계
Check 1: 의료기기 면책문구 자동 삽입 (soft-fix)
Check 2: regex로 다른 기종명 감지 시 hard-fail
Check 3: 위험 키워드 8개 탐지 → 서비스센터 안내 (hard-fail)
Check 4: LLM 정합성 검증 (보조 수단)
핵심 안전 로직(1~3)은 코드로 보장, LLM은 마지막 보조.
할루시네이션 방지 100% (21/21) · 안전 차단 100% (24/24)
Challenge 3

시멘틱 캐시 비용·지연 최적화

전체 워크플로우가 LLM을 평균 4회 호출하며 약 3~5초 소요. 반복 질문에 매번 이 비용을 지불할 필요 없음.

Solution — ChromaDB 기반 시멘틱 캐시
cosine 유사도 0.92 임계값으로 의미적 동일 질문 매칭
기종별 격리: model_id 필터로 교차 히트 방지
의도별 TTL 차등: troubleshoot 7일 / connect 14일 / install 30일 / clinical 90일
guardrail_passed=true인 응답만 캐싱 (오류 전파 방지)
캐시 히트 시 ≤200ms 응답 (LLM 파이프라인 대비 15~25배 단축)
Workflow — 11 Nodes
노드 역할 기술
model_router 사용자 질문에서 기종 자동 식별 LLM 텍스트 분류 (270S/580/770S/970S)
cache_lookup 시멘틱 캐시 조회 (cosine ≥ 0.92) ChromaDB 벡터 검색 + 기종별 격리
intent_router 질문 의도 분류 (5개 카테고리) 설치 / 연결 / 고장수리 / 임상 / 일반
전문 에이전트 ×5 의도별 전문 에이전트 실행 RAG (PDF 벡터 검색) + Tool Calling (SQLite)
guardrail 4단계 안전 검증 파이프라인 결정론적 Check 1~3 + LLM Check 4
cache_store 검증 통과 응답만 캐싱 guardrail_passed=true 조건부 저장
